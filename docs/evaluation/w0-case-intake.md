## 先准备这五项即可

| 材料 | 需要你提供或确认什么 | 可以暂时没有什么 |
|---|---|---|
| 论文方向 | 论文/项目名称、研究问题、目标读者 | 完整摘要或定稿标题 |
| 关键 claim | 最想表达的 1–3 个 claim，哪些不能说得太满 | 全部 claim 的完备列表 |
| 证据 | 支持与反证的原始出处、定位和适用范围 | 大规模自动导入 |
| 全文与段落 | 粗略叙事/outline，选一个有讨论价值的段落 | 全文正文 |
| 风格偏好 | 可选的认可文章/片段，以及你具体喜欢哪里 | 样本数量门槛或长问卷 |

先由研究者选定项目和授权的材料范围。不要因为某个文件在机器上、
在 Zotero 或 RKA 中，就自动纳入原型或风格分析。

## 风格样本：问“喜欢什么”，不问“模仿谁”

两三篇相关且作者认可的文章可以作为起点，零样本也可以。每个样本记录：

- 文章/片段的来源和定位，是作者自己写的、欣赏的，还是反面例子；
- 喜欢的具体特点，例如解释顺序、主体与动作、定义方式或信息密度；
- 哪些部分不希望学习，适用于哪个章节或句子功能；
- 是否只允许本地查看、是否允许未来分析，以及来源/权利限制。

选择用于分析不等于允许复制表达，也不等于允许把全文送给模型。
此次 W0 原型不会解析样本或调用模型。以后仍需单独确认处理范围。

## 从真实材料到可走查的脱敏包

1. 保留原始材料，制作独立工作副本；由研究者确认脱敏后仍保留关键论证困难。
2. 核对 claim—evidence 对应，区分来源准确、科学支持与研究者选择。
3. 预设一个有意义的变化，例如证据撤回或 claim 收窄，不预设研究者一定怎样回应。
4. 候选句只使用已授权的作者文本或明确标注的示例；不在语义批准前补写论文正文。
5. 研究者确认展示范围后，再适配原型的数据与测试。不得把私密文本复制进公开 Git 文件。

私密准备材料可保存在 `docs/evaluation/private/`，该目录已被 Git 忽略，
也不在建议的静态服务器目录内。它不是加密保险箱。不要将真实输入混入
`prototypes/w0/fixture.mjs` 后直接 commit/push。
