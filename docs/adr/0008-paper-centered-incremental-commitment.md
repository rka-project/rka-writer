## Context

The first design pass specified many artifacts and gates before observing a
researcher use them. A well-formed graph does not prove scientific support,
effective collaboration, or good prose. A subscription login does not prove
that execution cannot consume extra paid credits. A minimal prompt does not
prove that the host has no other context or tools.

The PI approved the design review and authorized this documentation revision
and its GitHub PR/merge. This accepts a direction, not a successful usability
study, working adapter, or production schema.

## Decision

Keep the Core/Writer/document authority boundary, exact historical versions,
researcher-owned meaning, late term locks, and one-intent sentence generation.
Use the following interpretation across the active RFCs.

1. **Different granularities.** Store fine-grained artifacts, discuss one
   consequential research or writing question, approve a displayed bundle of
   coupled changes, and generate one admitted sentence candidate set at a time.
   Bundle approval is bound to exact displayed versions, scope and impact; it
   does not authorize unseen artifacts or future prose.
2. **Paper-centered interaction.** Argument, structure and writing are views of
   the same paper. Contextual conversation is welcome; it is not canonical
   approval. Graph internals and receipts are inspectable on demand, not the
   default author experience. Fixed panels remain a prototype hypothesis.
3. **Local commitment with global awareness.** W1 includes a Paper Spine,
   section outline and paragraph allocation. Generation receives a compact
   paper context plus detailed paragraph context. Only the target branch's
   necessary ancestors must be ready; unrelated future sections may be
   provisional. Researchers may reopen decisions explicitly.
4. **Honest guarantees.** Structural checks enforce authorization, references,
   versions and bounded mutations. Evidence entailment, implicit broadening and
   rhetorical quality require review; they are not deterministic guarantees.
   Author approval and source-grounding fidelity are not scientific validation.
5. **Impact before rewriting.** Changed upstream versions create impact
   candidates. Known invalid dependencies block; unknown semantic effects
   require review and also block the affected production path. Proven
   non-semantic changes may be classified separately. Keep old bindings and
   text unchanged; record revalidation or a new version rather than silently
   rebinding accepted artifacts.
6. **Researcher-owned calibration.** Retain selected samples, grounded
   observations, scoped term/prose/tone preferences and exact term locks.
   Calibrate through comparisons for the same admitted intent. An accepted
   edit is not permission to learn a global rule. Whole sample papers are
   excluded from realization; a small, explicitly approved example set is an
   optional experiment with provenance and copy-risk review, not the default.
7. **Independent execution gates.** Official subscription authentication,
   included-usage-only billing, and actual context/tool/file isolation must each
   be established. Unknown conditions fail closed. Account type, prompt text,
   a model's self-report or a receipt generated by Writer is not attestation.
   No provider API, paid-credit continuation or local-model fallback is added.
8. **Learning before freeze.** Run an author walkthrough and narrow technical
   feasibility checks before freezing production contracts. W1 includes
   lightweight direct-edit reconciliation and cold-start recovery; full editor
   integration and a second host wait for evidence.

An explicitly requested, isolated, read-only whole-paper review is compatible
with this design. Only selected findings enter the decision queue; review does
not write prose or approve itself.

## Consequences and limits

- The three RFCs remain Provisional technical proposals under accepted product
  principles. Their merge does not mark W0 or W1 complete.
- The old UI/style ADR bodies remain historical; this ADR is authoritative
  where they prescribe a fixed layout, rules-only calibration, or later-only
  interaction validation.
- ADR 0002's no-silent-rewrite principle survives. Its blanket version-change
  language is refined into explicit impact classification and review.
- ADR 0003 constrains agent generation, not the human's ability to write notes
  or edit their own paper. Reconciliation preserves those edits.
- ADR 0005's subscription-included-only boundary survives; a successful auth
  probe alone cannot meet it.
- This change does not implement a runtime, exercise paid inference, deploy
  Writer, change Core contracts, or touch the Hugging Face track.

## Alternatives

Freezing every schema now risks optimizing an approval workflow before proving
its value. Returning to prose-first chat would lose the requested authority
boundary. The selected approach keeps the boundary and tests its smallest
useful interaction before committing to the implementation.
